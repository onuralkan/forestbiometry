## Risks

HTML page instead of the real file (a JS challenge that refreshes itself after 5 s; `content-type: text/html`, with CSP nonce). When this page arrives in place of an ES module (e.g. `assets/lab/core/importer.js`) the browser cannot load the module and the tool is never rendered; in trials it happened in one of three page openings. The "site not working" report of 10 Nov is most likely this. Not related to the code (files on the server are identical). The fix is on the hosting side: switching off the bot protection in the panel (Imunify360 "Anti-bot" / WebShield or the company's equivalent) or exempting the .js/.css files under `/assets/`; or asking the company.
